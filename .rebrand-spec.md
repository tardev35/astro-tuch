## 8. Hard rules that bite during this rebrand

- Only docx article content emits `<h1>/<h2>/<h3>`. Chrome (tickers, feeds,
  grids, login boxes, card labels, footer columns) uses `<p>`/`<span>` + an
  `aria-label` on the section. A second `<h1>` fails the build.
- No HTML comments (`<!-- -->`) in anything that renders — Astro ships them.
  Notes go in the frontmatter.
- Body copy: `text-left text-base leading-relaxed <colour>`. Headings may be
  centered on the heading element itself. No `mx-auto max-w-*` on page `<p>`s.
- Decorative emoji live in their own `<span aria-hidden="true">`, never inside
  the text of a label. No `href="#"`, no `onclick=`.
- `alt` describes the picture. Never `"logo"` or `"banner"`.
- Never type a domain, never build a URL with `+` — use `pageGraph()`.
  No `Review`, `AggregateRating`, `sameAs`, `address`/`PostalAddress` in JSON-LD.
- Never write `isActive` by hand; import `isActivePath` from `../lib/nav`.
- No `define:vars`, no `is:inline` script on an indexable page.
- Do not add a `<style>` block that only sets `.font-sans`.
- **Do NOT run `npm run build`** — the orchestrator runs the single build.
