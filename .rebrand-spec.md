### Vocabulary switch — this is the biggest trap this round

The outgoing brand **LOTTOPLUS was a เว็บหวย (lottery site)**. GOT777 is a **สล็อต/คาสิโน** site.
A find-and-replace of the brand name over the previous copy produces a slot site that talks
about หวยรัฐบาล and โพย, which do not exist in this brief.

**BANNED words on every GOT777 page** (they are the previous brand's product, not this one's):
`หวย` · `โพย` · `แทงหวย` · `ตรวจหวย` · `รัฐบาลไทย` · `ลาวพัฒนา` · `ฮานอย` · `หวยหุ้น`
· `อัตราจ่าย 2 ตัว / 3 ตัว` · `รอบออกรางวัล` · `ส่งโพย` · `งวด` · `เลขเด็ด` · `แนวทางหวย`

**Vocabulary GOT777 DOES use** (all of it from the brief): `เกมสล็อต` · `แพลตฟอร์มค่ายใหญ่`
· `ค่ายเกม` · `แจ็กพอต` / `แจ๊คพอต` · `ฟรีสปิน` · `ตัวคูณ` · `เกมโบนัส` · `สล็อตคลาสสิก`

## 7. Hard rules every agent must follow

1. **Never delete an unused component variant.** It is inventory for the next brand.
2. **Never run `npm run build`.** The orchestrator runs it once, at the end.
3. **No HTML comments (`<!-- -->`) in anything that renders.** Astro ships them verbatim to
   `dist/`. Strip existing ones from every component you retheme. Frontmatter `//` comments
   are fine and are where notes belong.
4. **Only article content may produce a heading.** Chrome (tickers, feeds, card labels,
   widget titles, login boxes, badges) renders its label as `<p>`/`<span>` + `aria-label` on
   the section. Never promote one to `<h2>` to give a section an accessible name.
5. **Body copy is `text-left text-base leading-relaxed`.** Headings may be centered, but put
   the centering on the heading, not on the card/section (it inherits into the slot).
   No `mx-auto max-w-4xl` on paragraphs in pages.
6. **One element per slot.** Multiple blocks → wrap them in one `<div>` yourself.
7. **Accessibility (these are build ERRORS):** decorative emoji need
   `<span aria-hidden="true">` as a *sibling* of the label, never inside its text; no
   `href="#"`, no `onclick=`; `alt` must describe the picture; FAQ = `<details>/<summary>`;
   a widget whose title is a `<p>` needs `aria-label` on its `<section>`.
8. **Never type a domain and never build a URL with `+`.** `pageGraph()` derives every URL
   from `site:`. No `Review` / `AggregateRating` / `sameAs` / `address` nodes in JSON-LD.
9. **Don't touch `src/lib/`** — `nav.ts`, `winnersFeed.ts`, `liveCounter.ts`, `schema.ts`,
   `brandProfile.ts` are the orchestrator's / permanent. Never inline their logic back into a
   component. Never write `isActive` by hand; import `isActivePath` from `../lib/nav`.
10. **Never use `define:vars`** on an indexable page (forces `is:inline` → build error).
11. **Images:** always give `<Image>`/`<Picture>` `widths` + `sizes`. `sizes` describes how
    wide the image is *drawn*. Only the hero gets `loading="eager" fetchpriority="high"` —
    everything else is `loading="lazy" fetchpriority="low" decoding="async"`.
12. **Don't add a `<style>` block containing only `.font-sans { font-family: var(--font-sans) }`** —
    it is a no-op that makes Astro stamp `data-astro-cid-*` on every element.
13. **`*FloatingBadge` variants have two known bugs — fix both before use:** the title badge
    ships `whitespace-nowrap` (replace with `w-[92%] max-w-2xl` + `text-center` so a real
    docx sentence wraps instead of blowing out the viewport), and the card's `pt-*` was sized
    for a one-line title (bump so a 2-line badge doesn't overlap the content: `pt-12`→`pt-16`,
    `pt-14`→`pt-18`).
