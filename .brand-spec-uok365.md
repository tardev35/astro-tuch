## §2 Palette

Read off `src/assets/palette.json` + the artwork. The brand is **gold metallic +
chrome silver on near-black warm brown**. `logo.webp` vivid #1 is `#a46b25`
(the gold "UOK"), the "365" below it is chrome silver, and `banner1`/`slide*`
dominants are `#0d0c0b` / `#1b140c` / `#2c1d0c` — a black hall lit by gold.
`src/assets/bg.json` is `{"mode":"color","color":"#000000"}` → pure black page.

One brand hue only (gold), with silver as a **metal accent**, never a second
brand colour. Separation comes from gold *brightness levels*, not a second hue.

| role | hex | where |
|---|---|---|
| gold light / champagne | `#f5d98a` | active links, light end of gradients, `<strong>` highlights, heading gradient start |
| **gold brand** | `#c8912f` | borders, menu underlines, divider rules, aura |
| gold mid (logo vivid #1) | `#a46b25` | mid gradient stop |
| gold deep | `#6d4412` | dark end of gradients, bottom rules |
| chrome silver | `#d8dbe0` | the "365" metal — second chip, second ring, heading gradient end. **Sparing.** |
| surface — bar/footer | `#0a0806` | navbar, footer, ticker base |
| surface — raised card | `#191108` | the lighter ContentBox skin |
| surface — mid card | `#120c07` | the middle ContentBox skin |
| surface — deep | `#070504` | deepest card / inset |
| ink on gold | `#191005` | text on any gold-filled button or badge |
| **body copy** (`BRAND_TEXT`) | `#ece1cc` | warm ivory — set in `brandProfile.ts`, inherited everywhere |

Measured contrast (all pass AA at `text-base`):
`#ece1cc` on `#191108` ≈ 13.4:1 · on `#120c07` ≈ 14.6:1 · on `#000000` ≈ 16.2:1 ·
`#f5d98a` on `#120c07` ≈ 12.1:1 · `#c8912f` on `#0a0806` ≈ 7.5:1 ·
`#191005` on `#c8912f` ≈ 6.5:1 · on `#f5d98a` ≈ 13.0:1.

**Not reversible:** `#c8912f` as *text* on a dark surface is fine, but a light
ink on a `#c8912f` fill falls to ~2.6:1. Gold fills always take the dark ink
`#191005`.

## §8 House rules that bite during this rebrand

1. **Only article content may produce a heading.** Chrome (ticker, winners feed,
   login widget, review cards, card labels, footer column titles) renders its
   label as `<p>`/`<span>` with the same classes, plus `aria-label` on the
   `<section>` where it named a region. A second `<h1>` fails the build.
2. **No HTML comments (`<!-- -->`)** in any rendered page or component — Astro
   ships them verbatim. Notes go in the frontmatter (`//`).
3. **No `define:vars`**, no `href="#"`, no `onclick=`. Decorative emoji live in
   their own `<span aria-hidden="true">`, never inside a text node or a prop.
4. **Never write a domain by hand.** `pageGraph()` from `src/lib/schema.ts`
   builds every JSON-LD URL. No `Review`, `AggregateRating`, `sameAs`, or
   `address`/`PostalAddress` nodes.
5. **One element per slot.** If a section needs a paragraph plus buttons, wrap
   them in one `<div>` yourself.
6. `*FloatingBadge` variants: grep the title badge for `whitespace-nowrap` and
   replace with `w-[92%] max-w-2xl text-center`; confirm the card's `pt-*`
   clears a two-line badge (`-top-6` offset, so badge height − 24px must be less
   than the card's top padding).
7. **Do NOT run `npm run build`.** The orchestrator runs the single build in
   Phase 5.
8. Prose inherits its colour from the card — do not put `text-[#…]` on a `<p>`,
   and do not add `mx-auto` / `max-w-*` to a paragraph.
